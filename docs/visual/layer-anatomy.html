A short textbook chapter

Bonsai Layer Anatomy

How a screenshot becomes a click, in linear algebra. You know vectors, dot products and linear maps. This chapter shows what those objects are doing inside the model, with small examples first and the real sizes second, and ends with why squeezing the model to three weight values hurts pointing before anything else.

Notation

Lower-case bold-free letters like x, q, k are vectors. Capitals like W, S are matrices. W ∈ ℝout × in means W has out rows and in columns, so it takes a vector of in numbers and returns one of out numbers. a · b is the dot product. ⊙ multiplies two vectors entry by entry. T is the number of tokens.

SECTION 1A vector is a state, a direction is a feature

Inside the model, each piece of the input (a word, or a small square of the screenshot) is represented by a list of 4,096 numbers. Think of it as a point in a 4,096-dimensional space. The individual numbers mean nothing on their own. What carries meaning is direction.

The model has learned that some direction in that space means "this is a button", another means "near the top of the screen", another means "the user asked about saving". To ask how strongly a state x has a feature, take the dot product with that feature's direction f:

x · f  =  |x| |f| cos(angle between them)        large when x points along f, zero when perpendicular
Small example

Pretend the space has 3 dimensions and the feature "is a button" is the direction f = (1, 0, 1). A state x = (2, 5, 1) has button-ness 2·1 + 5·0 + 1·1 = 3. A state x′ = (−1, 4, 0) has button-ness −1. The second number never mattered, because f is perpendicular to that axis.

Everything that follows is built from this one operation. A neural network is, to a first approximation, an enormous number of dot products arranged in layers.

Check yourself: with 4,096 dimensions, how many features can there be?

Only 4,096 directions can be exactly perpendicular to each other. But the model packs in far more features by using directions that are nearly perpendicular; in thousands of dimensions there is room for millions of those. The price is a little crosstalk between features, which matters later when precision is lost.

SECTION 2Three ways to read a matrix

You know a matrix as a linear map. In a neural network it helps to hold three readings of y = W x at once.

One matrix, read three ways
W = 1000111−10.5.5.5 x =201 y = W x =2121.5

As a shape. W is 4 × 3: it takes 3 numbers and returns 4. The shape alone tells you what it connects.

By rows: a bank of detectors. Each output is one row dotted with the input. Row 3 is (1, −1, 0), so the third output is 2·1 + 0·(−1) + 1·0 = 2: it measures "first feature minus second". Four rows, four questions asked of the same input.

By columns: a set of things to write. The output is also a weighted sum of the columns, with the input's entries as weights: 2·(1, 0, 1, .5) + 0·(…) + 1·(0, 1, 0, .5) = (2, 1, 2, 1.5). Each input feature, when present, writes its column into the output.

So a matrix in the model is two things glued together: its rows decide what to look for in the incoming state, its columns decide what to write into the outgoing one. Training adjusts both.

Reading the real shapes

The biggest matrices here are 12288 × 4096. By rows: 12,288 detectors, each a direction in the 4,096-dimensional state space. It answers 12,288 questions about one token. A 4096 × 12288 matrix does the reverse: it takes those 12,288 answers and writes a combination of its 12,288 columns back into the state.

Check yourself: Wk is 1024 × 4096. What goes in and what comes out?

A token's 4,096-number state goes in. 1,024 numbers come out: 1,024 detectors' answers. In section 5 those are cut into 4 groups of 256, each a "key".

SECTION 3From pixels to a sequence of vectors

The model never works on pixels. The screenshot is cut into 16×16-pixel patches; a first matrix turns each patch (its 1,536 raw numbers) into a vector of 1,152; a vision network of 27 layers refines those; then every 2×2 block of patches is merged by a final matrix into one vector of 4,096. So one image token stands for a 32×32-pixel square of the screen.

Notice what has happened to "where". Nothing in a vector's 4,096 numbers says which square of the screen it came from. Position is added separately, as a rotation applied inside the attention step (section 5). Keeping track of where things are is therefore a job the layers themselves must do well.

SECTION 4The stream: add, never replace

Stack the T vectors as rows of one table x ∈ ℝT × 4096. Every layer reads this table and adds something to it. Nothing is overwritten.

for each of the 32 layers:
    x ← x + Mixer( norm(x) )        tokens exchange information with each other
    x ← x + MLP( norm(x) )          each token is processed by itself

Picture a shared whiteboard with one row per token. Each layer reads the board, works something out, and writes it in a direction that later layers know how to read. Early layers write simple facts ("this patch has text"), later ones write conclusions ("the Save button is around here").

norm

Before reading, each row is rescaled to a standard length: norm(x) = x / rms(x) · (1 + w), where rms is the root-mean-square of the row and w is a learned vector of 4,096 gains. This keeps direction and discards overall size, so detectors downstream see inputs on a predictable scale.

SECTION 5Attention: a soft lookup made of dot products

The Mixer has to move information between tokens. For pointing, the place where the answer is being written must find out which image square matches the request. Full attention does this with a lookup.

Every token produces three vectors from its state, using three matrices:

q = Wq h        query: what am I looking for?
k = Wk h        key:   what do I offer to be found by?
v = Wv h        value: what do I hand over if found?

A token compares its query with every earlier token's key by dot product. A large dot product means "this one matches". The scores are turned into weights that are positive and sum to 1 (the softmax), and the token receives the weighted average of the values.

scorej = q · kj / √256
weightj = escorej / Σi escorei           softmax: exaggerates the largest scores
received = Σj weightj · vj
Small example

The query is q = (1, 0), already scaled up 8 times to make the lookup decisive. Four patches offer keys:

k₁ = (0.9, 0.1)    score 7.2    weight 0.689   ← the Save button
k₂ = (0.1, 0.9)    score 0.8    weight 0.001
k₃ = (−.5, 0.5)    score −4.0   weight 0.000
k₄ = (0.8, −.2)    score 6.4    weight 0.310   ← the button next to it

The right patch wins, but a similar-looking neighbour takes 31%. The token receives a blend of both values. If the scores were disturbed by ±0.5, the neighbour could win.

A lookup is only as sharp as the gap between the best score and the second best. Pointing needs the right square among about a thousand, many of which look alike.

The real sizes

h = norm(x)                                T × 4096
[q | gate] = h Wqᵀ     Wq ∈ ℝ8192 × 4096      16 heads, each a 256-number query and a 256-number gate
k = h Wkᵀ             Wk ∈ ℝ1024 × 4096      4 keys of 256, each shared by 4 heads
v = h Wvᵀ             Wv ∈ ℝ1024 × 4096      4 values of 256
A = softmax( q kᵀ / √256 )                 T × T per head: who looks at whom
Mixer(x) = ( (A v) ⊙ sigmoid(gate) ) Woᵀ   Wo ∈ ℝ4096 × 4096

Sixteen heads do this in parallel, each with its own 256-dimensional query, so one can look for "the word Save" while another looks for "things in the toolbar". Position enters here: before the dot product, each query and key is rotated by an angle that depends on the token's row and column on the screen, so the score also depends on relative position.

Check yourself: two buttons look identical. What does attention do?

Their keys are nearly equal, so their scores are nearly equal and the weight splits between them. Only the position rotation can tell them apart, which needs precise arithmetic on small angle differences.

SECTION 6The reading-order layers: a memory matrix

Full attention compares every token with every other, which costs T² work. So only every fourth layer does it. The other 24 use a cheaper device: they read the tokens once, in order, keeping a small memory matrix S that they write to and read from as they go.

The trick is that a matrix can store pairs. To store "under key k, remember value v", add the outer product k vᵀ to S. To recall, multiply by a query:

write:   S ← S + k vᵀ             a rank-one update
read:    Sᵀ q  =  Σ (q · ki) vi       each stored value, weighted by how well its key matches the query
Small example

Start with S = 0 (2 × 2). Store v₁ = (3, 1) under k₁ = (1, 0), then v₂ = (2, 5) under k₂ = (0, 1):

S =3125reading with q = (1, 0) gives Sᵀq = (3, 1). Exactly v₁.

That worked because the two keys were perpendicular. Read with q = (0.6, 0.8) and you get 0.6·(3, 1) + 0.8·(2, 5) = (3.4, 4.6): a mixture. Keys that are not perpendicular bleed into each other.

The real layer adds two refinements. Before writing it checks what the memory already returns for this key and writes only the correction (the "delta rule"), and it lets old content fade:

for each token t, in order, in each of 32 heads:      S ∈ ℝ128 × 128
    S ← αt S                              forget a little        (α between 0 and 1)
    S ← S + kt · βt ( vt − Sᵀ kt )ᵀ        write the correction   (β: how strongly)
    ot = Sᵀ qt                             read

[q | k | v] come from one matrix Wqkv ∈ ℝ8192 × 4096;  α and β from two tiny matrices of 32 × 4096

A 128 × 128 memory can hold at most 128 perpendicular keys. A screenshot has over a thousand squares. These layers must summarise; only the eight full-attention layers can go back and look at one exact square.

Check yourself: why does that matter for pointing?

Exact position has to travel through layers that cannot store a thousand separate things. So it is the full-attention layers, and the precision of their queries and keys, that pointing leans on. It also means a small error early on is hard to undo later.

SECTION 7The MLP: detect, then write

After tokens have exchanged information, each token is processed alone by the layer's MLP. It is the row view and column view of section 2, one after the other:

h = norm(x)
a = silu( Wgate h )           12,288 detectors; silu keeps positives, mostly silences negatives
b = Wup h                   12,288 more detectors
MLP(x) = Wdown ( a ⊙ b )      each active pair writes one column of Wdown into the stream

Wgate, Wup ∈ ℝ12288 × 4096      Wdown ∈ ℝ4096 × 12288

Read it as 12,288 small rules of the form "if the state looks like this (a row of Wgate) and has that much of this (a row of Wup), then add that (a column of Wdown)". This is where most of the model's knowledge lives, and most of its weights: the MLPs hold 54% of them.

SECTION 8Turning the last vector into digits

After 32 layers, the state at the position where the answer goes is read by one last matrix with a row for every token the model could write next:

scores = Whead norm(xlast)        Whead ∈ ℝ248320 × 4096
next token = the row with the largest dot product (after softmax, its probability)

Ten of those 248,320 rows are the digits 0 to 9. A coordinate like 589 is written as three separate choices: 5, then 8, then 9, each a fresh pass through all 32 layers with the digits so far appended. So for the model to write 5 first, the final state must already point more along the "5" row than along "4" or "6". Position, which began as "which square matched", has to have been converted into a direction that separates neighbouring digits.

Check yourself: which digit is hardest to get right?

You might expect the last one. But a box is usually wider than 1% of the screen, so several last digits are fine. Our measurements show the opposite: Bonsai is already unsure about the hundreds digit (right 61% of the time against the parent's 88%). It is unsure roughly where the element is, not just exactly where.

SECTION 9What ternary does to a matrix

In the parent model every entry of every matrix is a 16-bit number. Bonsai replaces each large matrix by a grid of only three values and a few multipliers:

W  ≈  C ⊙ S          C has entries −1, 0 or +1         one multiplier in S per group of 128 inputs in a row

Take the row view. A detector used to be any direction in 4,096 dimensions. Now, within each group of 128 inputs, it can only be a pattern of −1, 0, +1 times one number. The best such pattern still points roughly the right way, but not exactly.

A 30° error in one dot product is survivable. But the output of one layer is the input of the next, 32 times over, and sections 5 and 6 showed operations that depend on small gaps between scores. PrismML does not simply round the parent's weights; it retrains the ternary model so that the errors of one matrix are compensated by the others. That is why the pieces of Bonsai only work as a set.

The rotation trick

Rounding to three values is worst when a few entries are much larger than the rest, because one multiplier must serve a whole group. So before the multiply, Bonsai mixes the input with a fixed matrix H whose entries are all ±1/√n (a Walsh–Hadamard matrix), which spreads any spike evenly:

H =½11111−11−111−1−11−1−11H · (8, 0, 0, 0) = (4, 4, 4, 4)
y = ( C ⊙ S ) · H( s ⊙ x )        s: a fixed vector of ±1        H: fixed, costs no storage, and H H = I

Wup in the parent:   12288 × 4096 sixteen-bit numbers                    100.7 MB
Wup in Bonsai:       50.3 million codes at 2 bits + 393,216 multipliers    12.6 MB

Because H is its own inverse and preserves lengths and angles, this changes nothing mathematically; it only chooses a basis in which the matrix is easier to approximate.

Check yourself: what are the legal ways to change a Bonsai matrix and keep it a Bonsai matrix?

Change a multiplier (rescales a group of 128 entries in one row), set a code to 0 (delete a connection), or flip a code between −1, 0 and +1. Anything else needs more bits per weight. Those are exactly the moves the weight lab offers.

SECTION 10Why pointing breaks first

Put the pieces together. Answering a question in words needs the right features to be present, roughly. Pointing needs something stricter: one square out of a thousand must win a lookup against neighbours that look almost the same, the winning position must survive a stack of layers that cannot store it exactly, and at the end it must separate adjacent digits. Each step depends on small differences between dot products, and small differences are exactly what a 30° error per detector erodes.

What we have measured fits that picture:

MeasurementWhat it says
Pointing accuracy on ordinary screens: parent 95%, Bonsai 52%The skill is damaged, not gone: Bonsai finds the neighbourhood.
Hundreds digit acceptable 61% of the time (parent 88%), tens 72% (parent 94%)The error is in coarse-to-medium position, not the last digit.
Vision part byte-identical to the parent'sThe eyes are fine. The loss is in the 32 layers.
Giving Bonsai any one layer, or one kind of matrix, from the parent: no help, often harmThe matrices compensate for each other; a precise piece does not fit beside imprecise ones.
Giving it the parent's first 20 layers, keeping its own last 12: fully restored (73%). First 16: 44%. First 8: no change.The position information is lost in the middle of the stack, about layers 9 to 20. The final layers read it out correctly when it is there.

So the repair target is specific: the middle layers' ability to carry an exact position, in a model whose matrices must keep working together.

In the language of this chapter, the available repairs are: retune multipliers (lengthen or shorten groups of detector entries), delete or flip codes (redirect a detector within the ternary grid), give the middle layers more bits (finer directions, at a cost in file size), or retrain any of these in place on screens where the correct answer is known.
